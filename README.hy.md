# `sd-video-recovery`

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Platform](https://img.shields.io/badge/Platform-Windows%2010%20%2F%2011%20x64-lightgrey.svg)]()
[![Language](https://img.shields.io/badge/Language-Rust%202021-orange.svg)]()

Արագագործ, խստորեն read-only (միայն կարդալու իրավունքով) Windows CLI գործիք՝ FAT32 և exFAT ֆայլային համակարգերով SD քարտերից (տեսախցիկներ, GoPro, դրոններ, ձայնագրիչներ) ջնջված կամ quick-format եղած MP4 և MOV տեսանյութերը վերականգնելու համար։

[English documentation is available here: README.md](README.md)

## Ընդհանուր նկարագիր և շրջանակ

Երբ տեսանյութերը ջնջվում են, կամ երբ SD քարտը պատահաբար արագ ֆորմատավորվում է (quick format) տեսախցիկի, դրոնի կամ համակարգչի միջոցով, տեսանյութի բուն բայթերը հաճախ մնում են ֆլեշ հիշողության չհատկացված բլոկներում՝ մինչև դրանց վրա նոր նկարահանում կատարվի։

`sd-video-recovery`-ն նախագծված է հատուկ նման տեսանյութերը Windows միջավայրում անվտանգ, արագ և առավելագույն ճշգրտությամբ վերականգնելու համար.

- **Օպերացիոն համակարգ**՝ Windows 10 և Windows 11 (64-բիթ `x86_64`)։
- **Կրիչների աջակցություն**՝ SDSC, SDHC, SDXC և SDUC քարտեր մինչև 2 ՏԲ տարողությամբ՝ միացված ներկառուցված SD/MMC slot-ի կամ USB card reader-ի միջոցով։
- **Ֆայլային համակարգեր**՝ FAT32 և exFAT (MBR, GPT կամ առանց partition table-ի «superfloppy» կառուցվածքներ)։
- **Տեսանյութերի կոնտեյներներ**՝ MP4 և MOV ֆորմատներ, որոնք ստեղծվել են սիրողական կամ պրոֆեսիոնալ տեսախցիկների և դրոնների կողմից (GoPro, DJI դրոններ, Sony, Canon, Panasonic, Nikon, Blackmagic, iPhone/Android)։
- **Վերականգնման երկու փուլ**՝
  1. **Ֆայլային համակարգի մետատվյալների վերականգնում (Filesystem Metadata Recovery)**՝ Վերականգնում է ջնջված թղթապանակային գրառումները (`0xE5` նիշով FAT32-ում, directory entry set-երն ու `AllocationBitmap`-ի InUse դրոշակները exFAT-ում)։ Երբ կլաստերների շղթան (FAT chain) պահպանված է, նույնիսկ ֆիզիկապես ֆրագմենտավորված ֆայլերը լիարժեք վերականգնվում են։ Եթե ջնջման պահին FAT շղթան զրոյացվել է, գործարկվում է անվտանգ հաջորդական (contiguous extent) կանխադրված ռեժիմը։
  2. **Խորքային սեկվենցիալ հում քարվինգ (Deep Raw Carving)**՝ Կատարում է սկավառակի մեկանգամյա հաջորդական սկանավորում՝ որոնելով ISO-BMFF կոնտեյների բլոկները (`ftyp`, `mdat`, `moov`, `moof`)։ Տեսանյութերը վերակառուցվում են անմիջապես հում սեկտորներից։
- **Կրկնօրինակների հեռացում (Deduplication)**՝ Ավտոմատ կերպով համադրում է հում քարվինգի և ֆայլային համակարգի թեկնածուներին՝ առաջնահերթությունը տալով ֆայլային համակարգի գրառումներին (պահպանված օրիգինալ անվանումներով և կլաստերների քարտեզով)՝ բացառելով նույն ֆայլի կրկնակի դուրսբերումը։
- **Երկլեզու ինտերֆեյս**՝ Անգլերենի (`en`) և հայերենի (`hy`) լիարժեք աջակցություն, որն ավտոմատ համապատասխանեցվում է Windows-ի համակարգային լեզվին։

## Ոչ-նպատակներ և v1-ի սահմաններ

Հուսալիությունն ու անվտանգությունը երաշխավորելու համար հետևյալ գործառույթները գիտակցաբար դուրս են թողնված առաջին տարբերակի (v1) շրջանակից.

- ❌ **Ոչ մի Raw NAND / Chip-Off վերականգնում**՝ Գործիքը չի աշխատում սալիկից պոկված/առանձնացված հիշողության միկրոսխեմաների հետ և չի փորձում վերծանել արտադրողների գաղտնի wear-leveling ալգորիթմները։
- ❌ **Ոչ մի ֆիզիկապես այրված/խոտանված կոնտրոլերի վերականգնում**՝ Եթե քարտը չի ճանաչվում Windows Disk Management-ում կամ LBA 0-ում առաջացնում է անդառնալի ապարատային I/O սխալ, ծրագրային վերականգնումն անհնար է։
- ❌ **Ոչ մի տեղում (in-place) ֆայլային համակարգի վերանորոգում**՝ Ծրագիրը երբեք չի կանչում `chkdsk`, չի փոխում partition table-ը և ոչ մի բայթ չի գրում ելակետային SD քարտի վրա։
- ❌ **Ոչ մի վնասված վիդեո սթրիմի ավտոմատ վերանորոգում**՝ Չի կատարում H.264/H.265 կադրերի հարմարեցված վերակոդավորում (re-encoding)։
- ❌ **Ոչ մի հնարովի դեֆրագմենտացիա կորած շղթաների դեպքում**՝ Չի փորձում գուշակել կլաստերների պատահական հերթականությունը, եթե ֆայլը ֆիզիկապես ֆրագմենտավորված էր, իսկ FAT աղյուսակը ջնջվել է ֆորմատի ժամանակ։
- ❌ **Զրո տելեմետրիա / Զրո ցանցային կապ**՝ 100% աշխատում է օֆլայն, չունի ոչ մի արտաքին ցանցային զանգ կամ վիճակագրության ուղարկում։ Ձեր անձնական տեսանյութերը երբեք չեն լքում համակարգիչը։
- ❌ **Rust գրադարանի կայունություն**՝ v1-ում ներքին Rust API-ն հանրային կայունության երաշխիք չունի։ Պաշտոնական կայուն ինտերֆեյսներն են CLI հրամանները և տարբերակավորված JSON հաշվետվությունը (`report_version: 1`)։

## Անվտանգության երաշխիքներ

Վնասված կամ թույլ ֆլեշ կրիչների հետ աշխատանքը պահանջում է բացառիկ զգուշություն։ `sd-video-recovery`-ն ապահովում է անվտանգության հետևյալ անխախտ կանոնները.

1. **Բացառապես Read-Only մուտք դեպի սկավառակ**՝
   Ֆիզիկական սկավառակը (`\\.\PhysicalDriveN`) բացվում է Win32 `CreateFileW`-ով՝ միայն `GENERIC_READ`, `FILE_SHARE_READ | FILE_SHARE_WRITE` և `OPEN_EXISTING` դրոշակներով։ Գրելու որևէ թույլտվություն կամ փոփոխող IOCTL երբեք չի հարցվում։
2. **Համակարգային սկավառակի արգելափակում**՝
   Գործիքն ավտոմատ նույնականացնում է Windows-ի boot/system սկավառակը (որտեղ տեղակայված է `C:\Windows`-ը) և կտրականապես մերժում է այն բացել կամ սկանավորել։
3. **Storage Bus-ի ստուգում**՝
   Կրիչի միացման տեսակը ստուգվում է `IOCTL_STORAGE_QUERY_PROPERTY`-ի միջոցով։ Թույլատրվում են հանովի SD, MMC և USB կրիչները։ Ներքին սկավառակները (NVMe, SATA, RAID) կանխադրված կարգով արգելափակվում են՝ օգտատիրոջ պատահական սխալները բացառելու համար (պահանջվում է `--allow-fixed` դրոշակ և ձեռքով հաստատում)։
4. **Սկավառակի համարի պարտադիր հաստատում**՝
   Նախքան ինտերակտիվ սկանավորումը CLI-ն ցուցադրում է սարքի մոդելը, չափը, bus տեսակը, partition table-ը և պահանջում է ստեղնաշարից մուտքագրել սկավառակի համարը։
5. **Ելքային թղթապանակի բախման բացառում (Anti-Collision)**՝
   Ելքային թղթապանակը պետք է գտնվի **այլ ֆիզիկական սկավառակի վրա**, քան ելակետային SD քարտն է։ Ծրագիրը ստուգում է ելքային ծավալի ֆիզիկական տիրույթը և անմիջապես կանգ է առնում, եթե այն համընկնում է աղբյուրի հետ՝ բացառելով հենց վերականգնվող քարտի վրա նոր տվյալներ գրելը։
6. **Ատոմար ֆայլային դուրսբերում (`.part`)**՝
   Ֆայլերը նախ գրվում են ժամանակավոր `.part` ընդլայնմամբ (օրինակ՝ `cand-0001_GOPR1234.MP4.part`)։ Միայն հաջող ավարտից և վալիդացիայից հետո դրանք ատոմար վերանվանվում են վերջնական անվանմամբ։
7. **Վերագրման բացառում (`create_new`)**՝
   Ֆայլերն ու սեսիայի թղթապանակները բացվում են `create_new` կարգավորմամբ։ Գոյություն ունեցող ոչ մի ֆայլ երբեք չի վերագրվում կամ կարճացվում։
8. **Մեկանգամյա կրկնությամբ (Retry) կարդալու սահմանափակում**՝
   Սեկտորի ընթերցման I/O սխալի դեպքում կատարվում է ճիշտ **1 սեկտորային retry**։ Եթե այն կրկին չի կարդացվում, ձախողված բայթային օֆսեթը գրանցվում է `report.json`-ում, իսկ սկաները կանգ է առնում կամ մեկուսացնում թեկնածուին՝ բացառելով անվերջ փորձերը և քայքայվող ֆլեշի տաքացումը։
9. **Անվտանգ ընդհատում (`Ctrl+C`)**՝
   `Ctrl+C` (SIGINT) սեղմելիս ընթացիկ ժամանակավոր `.part` ֆայլն անմիջապես ջնջվում է, արդեն պատրաստ ֆայլերը պահպանվում են, ստեղծվում է ընդհատված `report.json` հաշվետվություն, իսկ ծրագիրն ավարտվում է `130` կոդով։

## Նախապայմաններ և արտաքին գործիքներ

`sd-video-recovery`-ն օգտագործում է FFmpeg գործիքակազմը տեսանյութերի ստուգման համար.

| Գործիք | Կարգավիճակ | Դերը |
| :--- | :---: | :--- |
| **`ffprobe`** | **Պարտադիր** | Կատարում է վերականգնված ֆայլերի արագ կառուցվածքային ստուգում՝ ստուգելով կոնտեյների վերնագրերն ու վիդեո սթրիմի պարամետրերը։ |
| **`ffmpeg`** | **Լրացուցիչ** | Պահանջվում է միայն `--full-verify` դրոշակի դեպքում։ Ամբողջությամբ դեկոդավորում է տեսանյութի բոլոր կադրերը՝ երաշխավորելով, որ ոչ մի կոտրված կադր առկա չէ։ |

> [!IMPORTANT]
> **FFmpeg-ի binary ֆայլերը ներառված չեն** `sd-video-recovery`-ի թողարկման zip արխիվում։ Դուք պետք է այն ունենաք համակարգում կամ նշեք ուղիները ձեռքով։

### FFmpeg-ի տեղադրումը Windows-ում

#### Տարբերակ 1. Windows Package Manager (`winget`) — Առաջարկվող
PowerShell-ում կամ Command Prompt-ում կատարեք հետևյալ հրամանը.
```powershell
winget install Gyan.FFmpeg
```
Տեղադրելուց հետո փակեք և նորից բացեք տերմինալը՝ `PATH`-ը թարմացնելու համար։

#### Տարբերակ 2. Chocolatey
```powershell
choco install ffmpeg
```

#### Տարբերակ 3. Ձեռքով ներբեռնում
1. Ներբեռնեք թողարկումը [gyan.dev/ffmpeg/builds](https://www.gyan.dev/ffmpeg/builds/) կայքից (օրինակ՝ `ffmpeg-release-essentials.zip`)։
2. Քաղեք արխիվը (օրինակ՝ `C:\ffmpeg`)։
3. Ավելացրեք `C:\ffmpeg\bin` թղթապանակը համակարգի `PATH` միջավայրային փոփոխականում, կամ ուղիղ նշեք դրանք `--ffprobe-path` և `--ffmpeg-path` դրոշակներով։

Տեղադրումը ստուգելու համար գործարկեք.
```powershell
sd-video-recovery doctor
```

## Տեղադրում և արագ մեկնարկ

1. Ներբեռնեք վերջին թողարկման արխիվը (`sd-video-recovery-v0.1.0-x86_64-pc-windows-msvc.zip`) GitHub Releases բաժնից։
2. Քաղեք արխիվի պարունակությունը ցանկացած թղթապանակում (օրինակ՝ `C:\Tools\sd-video-recovery`)։
3. Բացեք PowerShell-ը կամ Command Prompt-ը **Administrator** իրավունքներով (սա պարտադիր է ֆիզիկական սկավառակներից՝ `\\.\PhysicalDriveN`, կարդալու համար)։
4. Գործարկեք `sd-video-recovery list`՝ ձեր SD քարտի սկավառակի համարը գտնելու համար.
   ```powershell
   sd-video-recovery.exe list
   ```
5. Գործարկեք վերականգնման հրամանը՝ նշելով ելքային թղթապանակը ձեր համակարգչի կոշտ սկավառակի վրա (օրինակ՝ `D:\Recovered`).
   ```powershell
   sd-video-recovery.exe recover --disk 2 --output D:\Recovered
   ```

## CLI հրամանների տեղեկատու

### `sd-video-recovery list`

```text
    --lang <en|hy>    Ինտերֆեյսի լեզուն (կանխադրված՝ Windows համակարգային լեզուն)
    --json            Արտածել սկավառակների ցուցակը JSON ֆորմատով
    -h, --help        Ցուցադրել օգնությունը
```

```powershell
# Մարդամոտ աղյուսակային ցուցադրություն
sd-video-recovery list

# JSON ֆորմատով արտածում սկրիպտների համար

# Հայերեն լեզվով արտածում
```

### `sd-video-recovery recover`

Կատարում է տեսանյութերի խորքային վերականգնում նշված ֆիզիկական սկավառակից դեպի ժամանակային նշումով նոր սեսիայի թղթապանակ։

```text
ԿԻՐԱՌՈՒՄԸ:
    sd-video-recovery recover --disk <N> --output <ԹՂԹԱՊԱՆԱԿ> [ՕՊՑԻԱՆԵՐ]

ՊԱՐՏԱԴԻՐ ՓՈՓՈԽԱԿԱՆՆԵՐ:
    --disk <N>               Ֆիզիկական սկավառակի համարը N (համապատասխանում է \\.\PhysicalDriveN-ին)
    --output <ԹՂԹԱՊԱՆԱԿ>     Ելքային թղթապանակ (պարտադիր պետք է լինի ԱՅԼ ֆիզիկական սկավառակի վրա)

ՕՊՑԻԱՆԵՐ:
    --mode <MODE>            Սկանավորման ռեժիմ:
                               all        Նախ ֆայլային համակարգի մետատվյալներ, հետո deep raw carve (կանխադրված)
                               filesystem Միայն ֆայլային համակարգի մետատվյալների վերականգնում (FAT32/exFAT)
                               deep       Միայն հում ISO-BMFF քարվինգ
    --ffprobe-path <FILE>    ffprobe գործարկվող ֆայլի հստակ ուղին
    --ffmpeg-path <FILE>     ffmpeg գործարկվող ֆայլի հստակ ուղին
    --full-verify            Կատարել տեսանյութի բոլոր կադրերի դեկոդավորում ffmpeg-ով (դանդաղ, համապարփակ)
    --allow-fixed            Թույլատրել ներքին fixed սկավառակների սկանավորում (պահանջում է հաստատում)
    --lang <en|hy>           Ինտերֆեյսի լեզուն (կանխադրված՝ Windows համակարգային լեզուն)
    -h, --help               Ցուցադրել օգնությունը
```

#### Օրինակներ.
```powershell
# Լիարժեք ստանդարտ վերականգնում PhysicalDrive2-ից դեպի D:\Recovered
sd-video-recovery recover --disk 2 --output D:\Recovered

# Միայն մետատվյալների արագ վերականգնում (օրինակ՝ վերջերս ջնջված ֆայլերի համար)
sd-video-recovery recover --disk 2 --output D:\Recovered --mode filesystem

# Խորքային քարվինգ՝ կադր առ կադր ամբողջական դեկոդավորմամբ
sd-video-recovery recover --disk 2 --output D:\Recovered --mode deep --full-verify

# Հայերեն ինտերֆեյսով գործարկում
sd-video-recovery recover --disk 2 --output D:\Recovered --lang hy
```

### Ելքային կոդեր (Exit Codes)

Ծրագիրը տրամադրում է հստակ ստանդարտացված ելքային կոդեր ավտոմատացման և սկրիպտների համար.

| Կոդ | Անվանում | Նկարագրություն |
| :---: | :--- | :--- |
| **`0`** | `Success` | Գործողությունը հաջողությամբ ավարտվել է (`recover` սկանն ավարտվել է, կամ `list`/`doctor` հրամանը կատարվել է)։ |
| **`2`** | `InvalidArgs` | Սխալ հրամանի արգումենտներ, անհայտ դրոշակներ կամ բացակայող պարտադիր պարամետրեր։ |
| **`3`** | `SafetyPreflight` | Անվտանգության խախտում. ելքային թղթապանակը գտնվում է նույն սկավառակի վրա, թիրախը համակարգային սկավառակ է, թիրախը ներքին սկավառակ է առանց `--allow-fixed`-ի, հաստատումը մերժվել է, կամ ֆայլերի բախում է առաջացել։ |
| **`4`** | `SourceIo` | Ելակետային SD քարտից կարդալու անդառնալի սխալ՝ 1 սեկտորային retry-ից հետո։ |
| **`5`** | `ExternalTool` | Արտաքին գործիքը (`ffprobe` կամ `ffmpeg`) բացակայում է, անհասանելի է կամ վերադարձրել է անդառնալի սխալ։ |
| **`130`** | `Interrupted` | Գործողությունն ընդհատվել է օգտատիրոջ կողմից `Ctrl+C` (SIGINT) ստեղնաշարային կոմբինացիայով։ |

## Սեսիայի ելքային կառուցվածք

Յուրաքանչյուր վերականգնման գործողություն ձեր ելքային թղթապանակում ստեղծում է առանձին, ամսաթվով և ժամով նշված սեսիայի թղթապանակ։ Գոյություն ունեցող ֆայլերը երբեք չեն վերագրվում.

```text
<ելքային-թղթապանակ>/
└── session_20261108_143022/
    ├── validated/
    │   ├── cand-0001_GOPR0042.MP4
    │   ├── cand-0002_DJI_0105.MOV
    │   └── cand-0004_raw_00800000.MP4
    ├── partial/
    │   └── cand-0003_raw_00450000.MP4
    ├── report.json
    └── summary.txt
```

- **`validated/`**՝ Պարունակում է այն ֆայլերը, որոնք հաջողությամբ անցել են `ffprobe`-ի կոնտեյների և վիդեո սթրիմի ստուգումը (և կադրերի դեկոդավորումը, եթե միացված էր `--full-verify`-ը)։ Այս ֆայլերը պատրաստ են մոնտաժի և նվագարկման։
- **`partial/`**՝ Պարունակում է այն ֆայլերը, որոնք ունեն տեսանյութի բլոկներ, բայց չեն անցել լիարժեք ստուգումը (օրինակ՝ վերջնամասը կտրված է, ինդեքսը վնասված է)։ Պահպանվում են ձեռքով զննելու կամ մասնագիտացված վերանորոգման ծրագրերով բացելու համար։
- **`report.json`**՝ Մեքենայաընթեռնելի, տարբերակավորված ամբողջական հաշվետվություն բոլոր թեկնածուների, ֆիզիկական օֆսեթների, հեշերի և ստուգման արդյունքների վերաբերյալ։
- **`summary.txt`**՝ Տեղայնացված (հայերեն կամ անգլերեն) մարդամոտ տեքստային ամփոփագիր։

### Թեկնածուների կարգավիճակները (Status).
- **`validated`**՝ Ֆայլը դուրս է բերվել և `ffprobe`-ով հաստատվել է որպես վավեր տեսանյութ՝ առնվազն մեկ դեկոդավորվող վիդեո սթրիմով։ Տեղափոխվել է `validated/`։
- **`partial`**՝ Տեսանյութի մետատվյալները գտնվել են, բայց ֆայլը կտրված է կամ ստուգման ժամանակ առաջացրել է սխալներ։ Տեղափոխվել է `partial/`։

- **`io_error`**՝ Դուրսբերումը դադարեցվել է ելակետային SD քարտի սարքային ընթերցման persistent սխալի պատճառով։

### Վստահության մակարդակները (Confidence).
- **`high`**՝ Թղթապանակի գրառումն անվնաս է, կլաստերների շղթան կամ exFAT `NoFatChain`-ը պահպանված է, և ֆայլը հաստատվել է `ffprobe`-ով։
- **`medium`**՝ Թղթապանակի գրառումը գտնվել է, բայց կլաստերների շղթան զրոյացված է (կիրառվել է հաջորդական fallback), կամ հում քարվինգի թեկնածու՝ մաքուր սահմաններով։
- **`low`**՝ Կտրված բոքսեր, մեկուսացված `mdat` հատված կամ կառուցվածքային անոմալիաներ։

## Փորձարարական (Sacrificial) SD քարտի QA ստուգացանկ

Վերականգնումը լիարժեք փորձարկելու համար՝ առանց իրական նկարահանումները ռիսկի ենթարկելու, օգտագործեք առանձին **փորձարարական (sacrificial) SD քարտ** (օրինակ՝ 16 ԳԲ կամ 32 ԳԲ) և հետևեք այս քայլերին.

```text
[ ] ՔԱՅԼ 1: Նախապատրաստում և Բազային հեշեր
    1. Միացրեք փորձարարական SD քարտը card reader-ին:
    2. Ֆորմատավորեք այն որպես exFAT կամ FAT32:
    3. Պատճենեք 3-5 իրական թեստային MP4/MOV տեսանյութեր քարտի վրա (օր.՝ GoPro-ից կամ դրոնից):
    4. Հաշվարկեք և պահպանեք յուրաքանչյուր ֆայլի ելակետային SHA-256 հեշը.
       Get-FileHash E:\*.MP4, E:\*.MOV -Algorithm SHA256

[ ] ՔԱՅԼ 2: Ջնջված ֆայլերի սցենարի QA
    1. Ջնջեք մեկ կամ մի քանի տեսանյութ Windows Explorer-ի միջոցով (Shift+Delete):
    2. Գործարկեք՝ sd-video-recovery.exe list (համոզվեք ֆիզիկական սկավառակի համարում, օր.՝ 2):
    3. Գործարկեք՝ sd-video-recovery.exe recover --disk 2 --output D:\RecoveryTest --mode filesystem
    4. Համոզվեք, որ ջնջված ֆայլերը դուրս են բերվել 'validated/' թղթապանակում:
    5. Ստուգեք, որ վերականգնված ֆայլերի SHA-256 հեշերը 100% համընկնում են ելակետայինի հետ:

[ ] ՔԱՅԼ 3: Quick-Format սցենարի QA
    1. ՈՒՇԱԴՐՈՒԹՅՈՒՆ: Կրկին ստուգեք, որ ընտրված է ՄԻԱՅՆ փորձարարական թեստային քարտը:
    2. Windows Disk Management-ում կամ Explorer-ում կատարեք QUICK FORMAT թեստային քարտի վրա:
    3. Գործարկեք՝ sd-video-recovery.exe recover --disk 2 --output D:\RecoveryTest --mode deep --full-verify
    4. Համոզվեք, որ թեկնածուները գտնվել են չհատկացված տարածքից (raw carving):
    5. Համոզվեք, որ 'validated/' թղթապանակի տեսանյութերը բացվում են, և ffmpeg full-verify-ն անցել է առանց սխալների:

[ ] ՔԱՅԼ 4: Անվտանգության ինվարիանտների ստուգում
    1. Համոզվեք, որ ելակետային քարտի վրա ոչինչ չի գրվել (ստուգեք volume serial-ն ու timestamp-ը):
    2. Փորձեք գործարկել վերականգնումը՝ որպես ելք նշելով հենց նույն քարտը.
       sd-video-recovery.exe recover --disk 2 --output E:\RecoveryTest
       -> Համոզվեք, որ այն անմիջապես մերժվում է Ելքային կոդ 3-ով (Safety Preflight Failure):
    3. Խորքային սկանի ընթացքում սեղմեք Ctrl+C.
       -> Համոզվեք, որ ժամանակավոր .part ֆայլն անմիջապես ջնջվում է, իսկ ծրագիրն ավարտվում է Ելքային կոդ 130-ով:
```

Պաշտոնական թողարկումները տարածվում են ինքնաբավ ZIP արխիվով՝ հետևյալ անվամբ.

```text
sd-video-recovery-v<VERSION>-x86_64-pc-windows-msvc.zip
```

```text
sd-video-recovery-v0.1.0-x86_64-pc-windows-msvc.zip
├── sd-video-recovery.exe       (Release binary, stripped)
├── README.md                   (Անգլերեն տեխնիկական ուղեցույց)
├── README.hy.md                (Հայերեն տեխնիկական ուղեցույց)
├── LICENSE                     (MIT լիցենզիա)
├── THIRD_PARTY_NOTICES.md      (Բաց կոդով crate-երի հեղինակային իրավունքներ)
└── SHA256SUMS.txt              (Կրիպտոգրաֆիկ հեշեր)
```

> [!NOTE]
> Թողարկումները երբեք չեն ներառում `ffmpeg.exe` կամ `ffprobe.exe`։ Օգտատերերն օգտագործում են իրենց համակարգում տեղադրված FFmpeg-ը։

### Հեշերի ստուգում
Արխիվը ներբեռնելուց հետո դրա ամբողջականությունը կարող եք ստուգել PowerShell-ում.
```powershell
Get-FileHash .\sd-video-recovery.exe -Algorithm SHA256
```
Համեմատեք ստացված արժեքը `SHA256SUMS.txt` ֆայլի մեջ հրապարակված հեշի հետ։
